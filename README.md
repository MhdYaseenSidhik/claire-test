# claire-test — Sales & Churn Dashboard

Vite + React + TypeScript single-page app. SPRINT-1 delivers the **repo & data
foundation**: the SPA scaffold, a committed synthetic dataset, and an in-browser
CSV loader with a schema guard. The Overview, Sales, Risk and Insights sections
(SPRINT-4 onward) build on this.

## Prerequisites

- Node 20+ and npm

## Install

```bash
npm ci        # reproducible install from package-lock.json
# or: npm install
```

## Commands

| Command | What it does |
|---|---|
| `npm run dev` | Vite dev server (local iteration only) |
| `npm run build` | Type-checks and produces the production build in `dist/` |
| `npm run preview` | Serves the production build |
| `npm run lint` | ESLint (zero warnings allowed) |
| `npm run typecheck` | `tsc --noEmit` |
| `npm test` | Vitest unit tests |

## Data foundation

Two CSVs live under `public/data/` and are fetched at runtime by the loader:

- `sales_weekly.csv` — `week, region, revenue, orders, new_customers` (52 weeks × 4 regions)
- `customers.csv` — `customer_id, region, signup_date, mrr, tenure_months, churned` (600 rows)

They are **synthetic and deterministic**, regenerated by a seeded script:

```bash
python scripts/generate_data.py
```

Replace these files with real exports (same headers) to drive the dashboard with
production data — no code change required.

### Loader & schema guard

`src/data/loader.ts` parses the CSVs with [papaparse] and validates every row
against the expected columns and types. On a missing column, a non-numeric
`revenue`, or a `churned` value outside `{0,1}`, it throws a `SchemaError` naming
the file and the offending field, rather than letting bad data reach the UI. The
contract is pinned by `src/data/loader.test.ts`.
